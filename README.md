# ship-dag

[![tests](https://github.com/jakebromberg/ship-dag/actions/workflows/tests.yml/badge.svg)](https://github.com/jakebromberg/ship-dag/actions/workflows/tests.yml)

A [Claude Code](https://claude.com/claude-code) skill that ships a dependency DAG of already-filed GitHub issues to `main`, **one wave at a time**. Each issue flows through the cheapest capable subagent — Haiku triage, Sonnet implement, Opus review — and lands via rebase-and-merge, **auto-merged on green**. The main agent owns everything human-facing and stateful (DAG discovery, the ready-set, the HITL gates, the dependency-ordered merge queue); the expensive parallel implement→review work fans out to subagents.

The premise: a well-specced issue Sonnet-implements and survives the Opus gate cleanly. When that premise breaks — an ambiguous spec, a blocking finding, a CI/merge failure — that break is the signal to stop and grill the human.

Between the merge queue and the next wave, a **retrospective pass** (one read-only Opus subagent) reviews the merged surface holistically — the cross-PR duplication that per-PR review structurally misses, and remaining-plan drift — and, after human approval (HITL point D), files ghost-written refactor tickets into the remaining DAG and applies plan adjustments.

See [`SKILL.md`](./SKILL.md) for the full skill definition and the wave loop.

## Dependency: claude-orchestrator

The parallel **implement** fan-out is delegated to the [claude-orchestrator](https://github.com/jakebromberg/claude-orchestrator) engine — per-repo worktrees + CI, per-issue model/effort, `mergePolicy: "none"` (implement, run CI, open a PR, then STOP; the Opus review gate and merge queue stay in the skill). Point `CO_HOME` at a checkout of that repo (default `~/Developer/claude-orchestrator`); its `dist/` must be built (`npm run build` — `dist/` is committed, so a fresh clone already has it).

Engine sessions run under claude-orchestrator's machine-wide lease hook (`CO_LEASE_HOOK=on`, set inline on step 4b's engine invocation). The agent rules, pinned by `scripts/lease-rules.test.mjs` in `scripts/engine/prompt.md`, SKILL.md's Implement and Review blocks and `workflow.js`: a heavy command may wait minutes for a slot and must run in the foreground; a `lease: no slot after <n>s` denial means rerun, never a test failure or a reason to skip CI; after the second denial the session stops, comments on the issue, ends with the line `orchestrator-stop: lease-wait` and exits without pushing; never wrap a command in `cli-lease.js`. Lease reruns are not infra-failure retries under the Guardrails. Review and fix hand-offs are sized from lease capacity: steps 4d and 5 read `recommendedHandoff` from `resource-preflight.mjs` (`max(1, capacity − live.length)`, 0 at `critical`) before each hand-off, and a hand-off subagent that gives up on the lease returns its PR to the queue (`scripts/handoff-rules.test.mjs`).

## Project resolution (org-agnostic)

ship-dag resolves the target project from context, never assuming an org:

- **Repo** — a fully-qualified `owner/repo#N` wins; else inferred from the cwd (`gh repo view`); else `--org O` with a bare `repo`.
- **Org checkout root** (where per-repo worktrees are created) — derived from the resolved repo's checkout, i.e. the parent of `git rev-parse --show-toplevel`. Override with `SHIP_DAG_REPOS_DIR` (or `SHIP_DAG_PROJECT_ROOT`, which the skill already emits).
- **Checkout name and worktree location** — a repo's checkout is normally the directory named after it, with worktrees in an adjacent `<checkout>-worktrees/`. When no directory carries the repo's name, the engine uses the one whose `origin` remote is that repo (a submodule path or renamed clone). A SwiftPM package whose `Package.swift` takes `../` path dependencies gets its worktrees beside the checkout instead, so those paths keep resolving; `SHIP_DAG_WORKTREE_MODE=sibling|adjacent` overrides the detection. See `scripts/engine/repo-layout.mjs`.
- **Per-repo base branch + local CI** — from [`references/repo-ci-profiles.json`](./references/repo-ci-profiles.json), keyed by `owner/repo`. A repo absent there defaults to `main` with no post-session check (the emitter warns — an unverified wave is the dangerous failure mode).

## Install as a Claude Code skill

Clone and symlink into your skills directory:

```bash
git clone git@github.com:jakebromberg/ship-dag.git ~/Developer/ship-dag
ln -s ~/Developer/ship-dag ~/.claude/skills/ship-dag
```

## Tests

```bash
node --test 'scripts/**/*.test.mjs' 'eval/**/*.test.mjs'
```

The suite loads the topo-sort core, so `CO_HOME` must point at a checkout of [claude-orchestrator](https://github.com/jakebromberg/claude-orchestrator) with its deps installed (`npm ci` there — `dist/` is committed, no build). CI ([`.github/workflows/tests.yml`](./.github/workflows/tests.yml)) does exactly this on every push and PR, across Node 22 and 24.

## Layout

| Path | What |
|------|------|
| `SKILL.md` | The skill definition — arguments, the wave loop, HITL gates. |
| `scripts/plan-waves.mjs` | DAG fetch + wave planning (imports claude-orchestrator's topo-sort core). |
| `scripts/run-ci-profile.mjs` | Runs a repo's local-CI profile under claude-orchestrator's lease CLI (SKILL.md step 6.2): each command in its own subshell, exit code passed through, 75 on no slot, 64 on a setup error. |
| `scripts/emit-config.mjs` | Turns a cleared ready-wave into a claude-orchestrator engine config. |
| `scripts/lib/failure.mjs` | Routing of an engine report row (`routeFailure`: `review-gate`, `resource`, `find-pr`, `point-E`, `point-B`; a PR decides first, then an engine stop for memory pressure or a lease wait, `RESOURCE_STOPS`, is `resource`, checked before `find-pr`) and the stop helpers: `stopCiStatus` (a stopped row's PR is `"fail"` after a `retry` stop, else `"none"`), `resumeMode` (commits or a dirty tree resume in place, a clean tree re-runs filtered) and `ciStatusAfterProfile` (`run-ci-profile.mjs`'s exit status as a `ciStatus`). |
| `scripts/lib/wave-spec.mjs` | `filterSpec` and its CLI: narrow a ready-wave spec to the refs an engine stop left clean (with a new `--wave` label and `--state-dir`), so the filtered re-run never relaunches a `failed` row into its existing branch (SKILL.md step 5). |
| `scripts/engine/` | The engine-invocation path: `run.mts` (entry), `hooks.mts` (worktree + cutover), `repos-dir.mjs` (org-root resolution), `repo-layout.mjs` (per-repo checkout name + worktree root), `prompt.md`. |
| `references/tuning.json` | Versioned effort policy (review floor, reach→effort, implement map); `scripts/lib/tuning.mjs` loads, validates and resolves it. |
| `scripts/telemetry.mjs` | Per-issue + per-retro-pass run records (model-assignment efficacy). The `ingest-wave` subcommand (`ingestWave`) appends a wave's records derived from its engine report, sidecar entry (else matching config), failure digests and review rounds (from the `reviews/` of every run-family dir, since a retry dir keeps its rounds under the base run's), plus `--outcomes`, each that reached implement with the `cost.implement` read from its ref's transcript. The `escapes` subcommand reports the escaped-defect proxy (see `scripts/lib/escapes.mjs`). The `tripwires` subcommand evaluates `references/tripwires.json` (see `scripts/lib/tripwires.mjs`). The `audit <runId>` subcommand (`audit`) counts the terminal rows it examined (`terminalRows`, and `prRows` with a PR) and names, across the run family's dirs (`runFamilyDirs`), the reports with a terminal row no log record covers (`rowCovered`, handed the row's failure digest from the window ingest reads it through, `waveWindow`), the unreadable reports, and the sidecar entries and `config*.json` files no report matched (never reported: nothing to ingest); a run id no dir belongs to exits 1. |
| `scripts/resource-preflight.mjs` | Step 4's memory-pressure preflight beside the rate-limit one: reads pressure and lease status from claude-orchestrator (`$CO_HOME/dist`) and prints a proceed/wait/hitl decision with `recommendedParallel` and `recommendedHandoff` (`scripts/lib/resource.mjs` holds the pure threshold table). Nothing starts at `critical`; the wait cap ends in HITL point F (wait / start anyway / defer / stop), whose override is stamped as `pressureOverride` in telemetry. |
| `scripts/lib/wave-sidecar.mjs` | Append-only `ship-dag-wave.jsonl` sidecar (one line per wave): `waveSidecar` (built from the config `buildConfig` returned), `appendWave`, `waveContextMatches`, `findWaveContext`, and, for a wave emitted before the sidecar, `findWaveConfig` (the newest `config*.json` by mtime matching a ref set) and `entryFromConfig` (the sidecar-shaped entry built from it). `waveConfigs` lists every readable config, and `findWaveConfig` names the path of the file it chose as `configFile`. Both finders take an optional cutoff, so a later re-emit of the same ref set is not taken for an earlier report's routing. |
| `scripts/lib/wave-reports.mjs` | The one reader of a state dir's wave reports: `readWaveReport` (one report, parsed as `{path, id, report, startedAt}`, or with an `error` when it does not parse, has no `issues[]`, has a row with no `owner/repo#N` ref (checked first) or has no parseable `startedAt`; a refused report keeps its `startedAt` when that parses, so it still bounds an earlier wave's window), `readWaveReports` (`readWaveReport` over every `state/reports/*.json`) and `waveContextFor` (the routing a `{report, startedAt}` ran under: the sidecar entry as of `startedAt`, else the matching config's `entryFromConfig`, plus that `config`, its `configFile` path and the `source`), `configDirs` (where a state dir keeps its configs: the dir, then `state/`) and `runFamilyDirs` (the dirs under a base dir that `sameRun` a run id). `ingest-wave`, the escapes proxy and `audit` call them. |
| `scripts/lib/ref.mjs` | The telemetry modules' one parser and builder of `owner/repo#N` refs: `REF_RE` (one slash, no whitespace), `parseRef` (`{repo, number}` or null), `formatRef`, `isPr` (a positive integer only), `parsePr` (the one parser of a telemetry PR value: `N`, `'N'`, `owner/repo#N` or a PR URL to `{repo, pr}`, else null), `refKey` (a repo or ref case-folded, as GitHub compares names, for escapes' keys and cache dirs) and `sameRepo` (the same fold; record dedupe compares through it, while a report's lookups into its own rows and routing stay exact). |
| `scripts/lib/engine-fixture.mjs` | Test support (not a test file): `engineFixture` builds a base dir of engine state dirs — `<dir>/state/reports/`, `<dir>/ship-dag-wave.jsonl` (through `appendWave`), `config*.json` in the dir or in `state/`, `<dir>/reviews/`, `<dir>/state/failure-digest/` and any other file, with optional mtimes (`stamped`) — and returns `{base, dirs, cleanup}`; plus `putReport`, `putReview`, `putDigest` and the shared `stateRow`, `stateReport`, `sidecarEntry` and `engineConfig` builders. |
| `scripts/lib/run-id.mjs` | Run-id helpers: `mintRunId`, `canonicalRunId`, `runIdFromConfigName`, and `sameRun` (folds wave/retry suffixes, prefix, case). |
| `scripts/lib/review-rounds.mjs` | The one review-round matcher: `reviewRoundFiles` (a ref's round files across `reviews/` dirs, legacy `-rN`/`.iterN`/`.passN*` tags included, oldest first by mtime) and `isUnreadableEmpty` (the empty-beside-`.raw` signature). |
| `scripts/lib/wave-records.mjs` | `WaveRefusal` (a refusal to derive records, whose `kind` — `half-supplied`, `no-run-id` or `malformed-row` — is what `ingestWave` dispatches on, never the message) and `deriveWaveRecords`: a wave's telemetry issue records from its report, sidecar entry, failure digests, review rounds and `--outcomes` (worst verdict and its blocking findings, bounces, routing, `ciStatus`, `reportId`, dedupe by `sameEvent`; findings as `<category> <file>:<line> <summary>` strings; a rate-limit death is `deferred`; a half-supplied refusal names every ref under each cause); `TERMINAL`, the row statuses a wave records; `sameEvent`, the one event identity both use (`sameRun`, ref, `finalState` with a legacy rate-limited `error` read as `deferred`, `failureReason`, whether it reached implement, the same PR (as a number, so a hand-written `owner/repo#N` or PR URL is that PR) unless both merged, and, between records of different reports, `reportId` once either carries the row's `ran` (else only between PR-less failures, `error` or `blocked`, unless both are `blocked`)); `carriedOver`, whether a `ran: false` row is one an earlier report of the run family lists with the same status and PR, which derives no record of its own; and `rowCovered`, whether a log record is, by `sameEvent`, the event ingest would derive for a terminal row, which `telemetry.mjs audit` reads: it reads the row's rate-limit as ingest does, from the digest audit hands it, else the row's own `failureReason`, and only a record of the death covers a PR-less rate-limit death; it reads no `--outcomes`, so it takes a record's finalState and a find-pr row's PR as given, and its JSDoc lists the two disagreements with ingest that this accepts (`startedAt` and `--outcomes`). |
| `scripts/lib/transcript-cost.mjs` | `implementCost`: a ref's implement cost streamed from its stream-json transcript, over the sessions that wrote a result record and that no earlier record of the run family lists, each counted once (its last running `total_cost_usd`, its `usage` summed). |
| `scripts/lib/gh.mjs` | The `gh` CLI seam: `ghCli` (the default `gh`), `ghFailure` (a failed call's `{status, rateLimited}`, from `gh api`'s JSON stdout or the `(HTTP NNN)` on stderr; the one place gh's error text is matched), `withBackoff` (retries a rate limit with doubling waits) and `ghJson` (parsed output as `{value}`, or `{failure}` after a warning with the caller's prefix). |
| `references/tripwires.json` | One tripwire per tuning decision: the `metric` that picks its evaluator, `source` field, `trips` threshold, `minSample`, baseline, action and `reviewDate` (the *Review date* of its decision's entry in `references/decisions.md`, or of its own entry there for T-cost, whose decision is `all`: first the decision date + 60 days, then the answer date + 60 days after each review; a test fails when the two files disagree), plus T-escapes' documented blind spots. T-floor, T-review-latency and T-review-cost are not in it yet: they need the eval scorecards and W1/W5's review timing and cost fields. |
| `scripts/lib/tripwires.mjs` | The evaluators behind `telemetry.mjs tripwires [--escapes <file>] [--now ISO]`: each row of `tripwires.json` is judged over the current `tuningVersion`'s records as `tripped` (the whole Wilson interval, or a seeded bootstrap for a mean, clears the threshold), `holding`, `insufficient-data` or `pending-instrumentation` (no record carries its source field yet; shown, never an error), with `reviewOverdue` when its review date has passed. T-escapes reads a saved `escapes` run and never calls `gh`; T-coverage reads `audit`'s `terminalRows` and `prRows` per run family inside its `since` window and skips a run with no engine dir; a metric id with no evaluator throws. `scripts/lib/stats.mjs`'s `wilson` is the interval. |
| `scripts/lib/escapes.mjs` | The escaped-defect proxy behind `telemetry.mjs escapes`: `shipDagPrs` (the population: telemetry `pr` fields, engine report rows' `prNumber`, and, for a sidecar ref with neither (and no PR in a report skipped for a malformed row ref or its `startedAt`), its one merged `orchestrator/` closing PR, cached in `cacheDir` once the issue is closed; a sidecar ref that is not an `owner/repo#N` string is skipped with a warning), `findEscapes` (each merged PR's view cached beside the day cache; per PR whose 30-day window has closed, the reverts and bug-signalled follow-ups citing it, from per-repo per-merge-day candidate searches cached under `$SHIP_DAG_ESCAPES_DIR` (in a format-version subdir; day files in their own `days-v<N>/` under it, so a day-shape change leaves PR views and closing answers cached; each candidate stored as only the fields classify and findEscapes read, its body only with a fix or bug signal) a settling day after the day's window closes, with bounded rate-limit backoff; a reverted sha GitHub has no commit for is permanently unresolved and does not keep its day uncached), `cites` and `citesStrongly` (a citation right after a closing keyword or causal phrase, on the same line; a revert is always strong), and `escapeReport` (rates by merge month and `tuningVersion`: `escaped`/`rate` count any citation, `strong`/`strongRate` only PRs with a strong one; a PR candidate closed unmerged, by its stored `state`, is no escape). |
| `references/` | CI profiles, model/effort matrix, escalation policy, review + retrospective + eval schemas. |
| `eval/` | Offline eval harness for the model-assignment study. |
| `docs/` | [Field report](./docs/field-report.md) from the first production run, plus a runnable anonymized [telemetry sample](./docs/examples/run-sample.jsonl). |
